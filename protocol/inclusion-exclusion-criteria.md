# Inclusion and Exclusion Criteria

**Project:** SLR - Traceability Links Recovery (GPT-4 vs IR methods)

## 1. General Criteria

| Code | Description |
|---|---|
| **IC-L** | Written in English. |
| **IC-T** | Published in a peer-reviewed conference or journal (no blogs, theses). |
| **IC-E** | Contains empirical results (at least one table/figure with metrics). |
| **EC-D** | Duplicate paper. |
| **EC-A** | Full-text is unavailable. |
| **EC-S** | Short paper (under 4 pages, abstract-only, or poster). |
| **EC-N** | Lacks empirical validation (vision papers, tutorials, editorials). |

## 2. Topic-specific Criteria

| Code | Field | Description |
|---|---|---|
| **IC-Y** | Minimum Year | **>= 2020**: Emergence of LLMs (GPT-3/GPT-4) in Software Engineering. |
| **IC-P** | Target Task | **Requirement-to-source-code traceability** (Focus on class-level granularity). |
| **IC-I** | Intervention | Uses **LLMs** (e.g., GPT, zero-shot/few-shot) OR **IR methods** (e.g., VSM, LSI, BM25). |
| **EC-O** | Out-of-scope | **Exclude:** Code Summarization, Bug Localization, and Fault Prediction. |
